# V2: selective expert team CLI

V2 adds real Microsoft Agent Framework agents to the synthetic shortage case.
V1 (`decision_demo.py`) and the recorded website remain unchanged.
Both model families use **your existing Azure Foundry resource/deployments**.
`agent-framework-openai` and `AsyncOpenAI` are protocol adapters, not public
OpenAI service access. Public OpenAI environment settings cannot change the
fixed, validated Azure URL or explicit Entra token audience.

```text
Decision-1 independent expertise questions
  -> selected Supply-chain / Production / Commercial agents
  -> synthetic read-only fixture tools -> Coordinator
  -> Decision-1 validation -> deterministic approval/evidence review
  -> one framework human clarification
  -> affected specialists + Coordinator + validation -> final advisory/handoff
```

Selection uncertainty pauses before agents. No repeated debate or arbitrary
manager replanning. Unaffected findings are reused during the one continuation.
Human evidence is labeled unverified and cannot grant spending/engineering
authority, rewrite fixture facts, or bypass policy. No plant actions are executed.
Refreshed findings must retain every previous unresolved unknown unless relevant
typed human evidence is supplied and cited; dropping an unknown fails explicitly.

## Setup and run (PowerShell)

Python 3.11+, Azure CLI, existing Entra sign-in, suitable existing Decision-1
and GPT Chat Completions deployments, authorized network path, and permission
to call those deployments are required. Nothing is provisioned or granted.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-v2.txt

# Reuse your existing authorized Azure CLI sign-in; no keys.
$env:FOUNDRY_ENDPOINT = 'https://YOUR-RESOURCE.services.ai.azure.com'
$env:DECISION_DEPLOYMENT = 'YOUR-DECISION-1-DEPLOYMENT'
$env:LLM_DEPLOYMENT = 'YOUR-GPT-DEPLOYMENT'

.\.venv\Scripts\python.exe decision_demo_v2.py --help
.\.venv\Scripts\python.exe decision_demo_v2.py --example supply-chain
```

The last command makes **live, billable Azure model requests**. Only help and
tests are offline. Agent-issued smoke testing requires separate bounded user
approval; no new live inference has been performed for this implementation.
Model responses and actual request count can differ from offline tests.

Flags `--endpoint`, `--decision-deployment`, `--llm-deployment` override the same
environment variables as v1. Endpoint must be an HTTPS Azure resource root,
not a project/inference API URL, public OpenAI URL, or a URL with credentials,
port, query, or fragment. Only `--example supply-chain` is supported in v2.
Decision-1 uses `https://cognitiveservices.azure.com/.default`; GPT v1 uses
`https://ai.azure.com/.default` through an explicitly configured Azure token
provider. Existing deployment permissions remain administrator-managed.

## One terminal response

When a framework request event occurs, the CLI lists allowed evidence keys and
accepts one JSON line:

```json
{"kind":"clarify","updates":{"recovery_capacity_assemblies":100}}
```

Other possible requested fields: `shipment_arrival`, `material_availability_note`,
`customer_commitment`, `proposal_feedback` (bounded nonempty strings).
Only requested keys are accepted, at most four updates. `recovery_capacity_assemblies`
must be a nonnegative integer, not a quoted number or boolean.
Reject or escalate without additional inference:

```json
{"kind":"reject"}
```

```json
{"kind":"escalate"}
```

There is **no approval/accept action**. If only mandatory approvals remain, the
terminal offers reject/escalate; clarification cannot clear them. Invalid input,
EOF, interruption, noninteractive stdin, or a 300-second human deadline leaves
review pending. No reprompt or automatic acceptance.

## Grounding and bounded cost

Tool data is synthetic, not live inventory/shipment/build/customer data:
480 needed, 310 available, shortfall 170; delayed shipment; $4,200 freight
above $2,500 authority; unapproved alternate; unknown arrival, recovery capacity,
and customer commitment. Tools cannot write, fetch URLs, or choose files.

At most three specialists plus one Coordinator, two assessments total.
Each specialist invocation permits at most three actual GPT attempts and two
unique fixture tools. Coordinator permits one GPT attempt, no tools.
Hard total maximum: **20 GPT + 3 Decision-1 = 23 HTTP attempts**, including
failed attempts and tool-result turns; at most 12 tool executions. These are
worst-case ceilings, not expected calls. A normal three-expert one-tool-round
assessment uses seven GPT and two Decision-1 attempts. Refreshing one affected
expert similarly adds three GPT and one Decision-1.

Framework iteration and tool limits are supplemented with pre-dispatch guards:
even the framework's forced final completion cannot exceed the cap. No SDK
retries, repair calls, or hidden inference loops. Sequential dispatch and a
rolling-minute limiter cap this process at 10 GPT / 20 Decision-1 attempts;
other callers can still cause HTTP 429, which stops without retry.

Request timeout 60s; credential subprocess 15s; fixture tool deadline 2s;
cumulative active run 900s including quota waits; human wait 300s; overall
wall deadline 1200s. Human waiting pauses the active clock and is limited by
the human and wall deadlines, not the remaining active time.
Worst-case calls can take minutes and may exhaust time
before reaching their count ceiling. Probability threshold 0.70 is an
illustrative policy, not a quality/safety guarantee. Probabilities and optional
model-reported confidence are printed separately.

Exit 0 means advisory completion or explicit human reject/escalate, **not
real-world success or permission**. Exit 1 is an execution/contract failure;
exit 2 is pending/unresolved handoff. Authentication/network/429/refusal/
truncation/schema/evidence/tool/limit errors stop explicitly.

## Offline development

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Tests use actual framework agents, tool invocation, executors and request/resume
with fake credentials and a wire-compatible mocked Azure transport. They make
no model calls. They verify Azure-only URLs/audiences even with ambient public
OpenAI settings, typed provenance, fixed affected-team mapping, approval
constraints, transport/tool budgets, deadlines, failure handling, and v1 behavior.
No mocked transcript is represented as live evidence.

Pinned framework core 1.21.0 / provider 1.15.0 are installed from the configured
feed. Provider 1.15.0 is the user-approved available-feed adjustment to the
initial 1.16.0 design reference. SDK/transport pins reflect the verified runtime;
no package-feed override or TLS bypass is required.
See the [approved design](superpowers/specs/2026-10-14-decision-model-v2-design.md)
and [implementation plan](superpowers/plans/2026-10-14-decision-model-v2.md).
